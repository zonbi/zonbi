# 推し活グッズ 買い物代行まとめアプリ

推し活グッズなどの買い物代行を複数人から受けるときに、注文を1つのURLで集めて整理するWebアプリです。
PHP + MySQL だけで動くので、CoreServer などのレンタルサーバーにそのまま置けます（フレームワーク・Composer不要）。

## できること

**代行する人（管理者）**
- タイトル・説明（注意事項）・受付締切を決めてセッションを作成
- 依頼者に送る **共有URL** と、自分用の **管理用URL** が発行される（ログイン不要）
- 表示を切り替えて確認
  - **依頼者別**：1人ずつの依頼内容と請求額（点数・合計金額）
  - **商品別（買い物リスト）**：同じ「商品名・色・型・単価」の必要数を合算し、誰が何個かの内訳つき
  - **全件一覧**
- 「購入済み」チェック（現地で買ったものに印をつける）
- **みんなの依頼を公開**：オンにすると、記入者全員が全員分の依頼一覧（依頼者別・商品別の合計、購入済み状況）を見られる（初期設定は非公開）
- 依頼の編集・削除、受付の締切/再開、CSVダウンロード（Excel対応・BOM付き）

**依頼する人**
- 共有URLを開いて入力するだけ（登録不要）
  1. 誰が（お名前）
  2. 何を（商品名・色・型）
  3. 何個
  4. 単価 → 小計と合計が自動計算
- 「＋ 商品を追加」で複数商品をまとめて依頼
- 自分が登録した依頼はあとから編集・削除できる（同じブラウザから。締切後は不可）
- 他の依頼者の内容は見えません（代行者が「みんなの依頼を公開」をオンにした場合は全員分を閲覧可。編集できるのは自分の依頼だけ）

## ファイル構成

```
index.php        トップ（セッション作成）
s.php            依頼者用ページ（共有URL）
admin.php        代行者用 管理ページ（管理用URL）
export.php       CSV出力
assets/          CSS / JavaScript
lib/             設定・共通処理（.htaccess でブラウザからアクセス不可）
  config.sample.php  設定ファイルのひな形
sql/schema.sql   テーブル作成SQL
```

## CoreServer への設置手順

1. **データベースを作成**
   コントロールパネル →「データベース」→ MySQL を新規作成。
   表示される **ホスト名・データベース名・ユーザー名・パスワード** を控えます。

2. **テーブルを作成**
   コントロールパネルから phpMyAdmin を開き、作成したデータベースを選択 →「インポート」で `sql/schema.sql` を読み込みます
   （または「SQL」タブに `schema.sql` の中身を貼り付けて実行）。

3. **設定ファイルを作る**
   `lib/config.sample.php` をコピーして `lib/config.php` を作り、手順1の情報を記入します。

   ```php
   'db' => [
       'host'     => 'localhost',      // CoreServerに表示されたホスト名
       'port'     => 3306,
       'name'     => 'xxxx_zonbi',
       'user'     => 'xxxx_zonbi',
       'password' => '********',
   ],
   'base_url' => 'https://example.com/oshi',  // 設置先URL（空欄なら自動判定）
   ```

4. **アップロード**
   FTP（またはファイルマネージャー）で、このフォルダの中身を `public_html/` 以下の好きな場所（例 `public_html/oshi/`）にアップロードします。
   `.htaccess`（ルート・`lib/`・`sql/`）も忘れずにアップロードしてください（隠しファイル扱いのFTPソフトに注意）。

5. **PHPバージョン**
   コントロールパネルのサイト設定で PHP **8.0 以上**（推奨 8.2 以降）を選択します。

6. **SSL（https）を有効化**
   管理用URLにキーが含まれるため、無料SSL（Let's Encrypt）を有効にして https で使ってください。

7. ブラウザで `https://example.com/oshi/` を開き、セッションを作成できれば完了です。

### 動作確認できない場合
- 「lib/config.php がありません」→ 手順3を確認
- 500エラー / DB接続エラー → `config.php` のホスト名・DB名・ユーザー・パスワード、PHPバージョンを確認
- `https://example.com/oshi/lib/config.php` をブラウザで開いて **403 になること** を確認してください（設定が見えないことの確認）

## アップデート時のデータベース更新

すでに `sql/schema.sql` でテーブルを作成済みの場合、新機能のために次のSQLを **1回だけ** phpMyAdmin で実行してください
（DBを選択 →「インポート」でファイルを選ぶ、または「SQL」タブに貼り付けて実行）。既存のデータはそのまま残ります。

| ファイル | 内容 |
|---|---|
| `sql/migrations/001_add_show_all.sql` | 「みんなの依頼を公開」機能の列を追加 |

新しく設置する場合は `sql/schema.sql` だけでOKです（上記は含まれています）。

## セキュリティについて
- 管理用URLは推測できないランダムなキー（128bit）付き。DBにはハッシュのみ保存しています。**管理用URLは他人に共有しないでください。**
- 依頼者の「自分の依頼」判定はブラウザのCookieで行います。別の端末・ブラウザで登録した分の変更は、代行者が管理ページから行えます。
- SQLはすべてプリペアドステートメント、出力はエスケープ、フォームはCSRFトークンで保護しています。
- CSVは Excel の数式インジェクション対策済みです。

## ローカルでの動作確認（開発者向け）

```sh
mysql -uroot -e "CREATE DATABASE zonbi CHARACTER SET utf8mb4"
mysql -uroot zonbi < sql/schema.sql
cp lib/config.sample.php lib/config.php   # DB情報を編集
php -S 127.0.0.1:8080
```
