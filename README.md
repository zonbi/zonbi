# 代行さん（推し活グッズの買い物代行まとめアプリ）

推し活グッズなどの買い物代行を複数人から受けるときに、注文を1つのURLで集めて整理するWebアプリです。
PHP + MySQL だけで動くので、CoreServer などのレンタルサーバーにそのまま置けます（フレームワーク・Composer不要）。

## できること

**代行する人（管理者）**
- タイトル・説明（注意事項）・イベントURL・受付締切を決めてセッションを作成
- 依頼者に送る **共有URL** と、自分用の **管理用URL** が発行される（ログイン不要）
- 表示を切り替えて確認
  - **依頼者別**：1人ずつの依頼内容と請求額（点数・合計金額）
  - **商品別（買い物リスト）**：同じ「商品名・色・型・単価」の必要数を合算し、誰が何個かの内訳つき
  - **全件一覧**
- 「購入済み」チェック（現地で買ったものに印をつける）
- **みんなの依頼を公開**：オンにすると、記入者全員が全員分の依頼一覧（依頼者別・商品別の合計、購入済み状況）を見られる（初期設定は非公開）
- 依頼の編集・削除、受付の締切/再開、CSVダウンロード（Excel対応・BOM付き）

**依頼する人**
- 共有URLを開いて入力するだけ（登録不要）
  1. 誰が（お名前）
  2. 何を（商品名・色・型）
  3. 何個
  4. 単価 → 小計と合計が自動計算
- 「＋ 商品を追加」で複数商品をまとめて依頼
- 自分が登録した依頼はあとから編集・削除できる（締切後は不可）
  - 登録後に表示される **「あなた専用の編集URL」** を開けば、別のスマホ・PC・ブラウザからでも編集できる
- 他の依頼者の内容は見えません（代行者が「みんなの依頼を公開」をオンにした場合は全員分を閲覧可。編集できるのは自分の依頼だけ）

## 代行者のGoogleログイン（任意）

代行者がGoogleでログインすると、作成したセッションが「マイページ」に保存され、管理用URLがなくても、どの端末からでも管理できます。
ログインしなくても従来どおり管理用URLで使えます。ログイン前に作ったセッションは、管理ページの「マイページに登録」で追加できます。

設定手順:
1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. 「APIとサービス」→「OAuth同意画面」（Google Auth Platform）でアプリ名・サポートメール・
   ホームページ（`https://…/index.php`）・プライバシーポリシー（`https://…/privacy.php`）・利用規約（`https://…/terms.php`）を登録し、
   スコープは `openid` `email` `profile` のみ。対象は「外部」、公開ステータスを「本番環境」にする
3. 「認証情報」→「OAuthクライアントID」→ 種類「ウェブアプリケーション」
   - 承認済みのリダイレクトURI: `https://（設置URL）/google_callback.php`
4. 発行されたクライアントID・シークレットを `lib/config.php` の `google` に記入
5. phpMyAdmin で `sql/migrations/003_add_google_login.sql` を実行（新規設置なら `schema.sql` に含まれています）

## 犯罪利用対策・運営者コンソール

- **運営者コンソール** `console.php`：全セッション・全依頼の検索（タイトル・依頼者名・商品名・メモ・IP・メール）、詳細表示、削除、受付停止
- **危険ワード検知**：保存時に「大麻」「覚醒剤」「拳銃」「スーパーコピー」などを検知して印をつける（自動削除はしない）。
  カタカナ/ひらがな・全角/半角・空白の違いは区別しない。語の追加は `moderation.extra_words`
- **通報**：依頼者ページ下部の「不適切な内容を報告」から。同じIPから1時間5件まで
- **記録**：セッション作成・依頼登録・通報時のIPアドレスとブラウザ情報を保存
- **通知**：検知・通報を `moderation.notify_email` にメール通知

`lib/config.php` の設定例:

```php
'moderation' => [
    'admin_emails'     => ['you@example.com'],   // Googleログインでコンソールに入れるアカウント
    'console_password' => '12文字以上の長いパスワード', // Googleログインを使わない場合
    'notify_email'     => 'you@example.com',
    'notify_from'      => 'noreply@office-saya.com',
    'extra_words'      => [],
],
```

## 広告エリア・アフィリエイト（Amazon・楽天）

**関連グッズを探す（自動）**：`lib/config.php` の `affiliate` に ID を設定すると、依頼者ページの下部に
「関連グッズを探す」欄が表示され、依頼された商品（商品名＋色＋型）ごとに Amazon・楽天の検索リンクを自動作成します
（自分の依頼のみ。「みんなの依頼」公開中は全員分。最大8件）。

```php
'affiliate' => [
    'amazon_tag' => 'yourname-22',                          // AmazonアソシエイトのトラッキングID
    'rakuten_id' => '1a2b3c4d.5e6f7a8b.1a2b3c4d.5e6f7a8b', // 楽天アフィリエイトID
],
```

**バナー枠（左右・下部）**：`ads/sample/` のファイルを `ads/` にコピーし、ASPで発行したバナーのHTMLを貼り付けます。

| ファイル | 表示場所 |
|---|---|
| `ads/left.html` / `ads/right.html` | 左右（画面幅1320px以上のときだけ。160×600 などの縦長バナー向け） |
| `ads/bottom.html` | 全ページ下部（スマホでも表示） |

ファイルがない・コメントだけの場合は枠ごと非表示。`ads/*.html` は配布物に含まれないため、アップデートで上書きされません。
運営者コンソールには広告を表示しません。広告が有効なときはフッターに広告表記（Amazonアソシエイトの必須文言を含む）が出ます。

## 利用規約・運営者情報

- `terms.php`（利用規約・免責事項）、`privacy.php`（プライバシーポリシー）、`about.php`（運営者情報）を同梱し、全ページのフッターにリンクしています。
- 運営者名・連絡先などは `lib/config.php` の `operator` に記入してください（`config.sample.php` 参照）。空欄の項目は「未設定」または非表示になります。
- セッション作成時は規約への同意チェックが必須、依頼送信時は「送信すると同意したものとみなす」旨を表示します。
- 規約文はひな形です。必要に応じて専門家の確認を受けてください。


## CoreServer への設置手順

1. **データベースを作成**
   コントロールパネル →「データベース」→ MySQL を新規作成。
   表示される **ホスト名・データベース名・ユーザー名・パスワード** を控えます。

2. **テーブルを作成**
   コントロールパネルから phpMyAdmin を開き、作成したデータベースを選択 →「インポート」で `sql/schema.sql` を読み込みます
   （または「SQL」タブに `schema.sql` の中身を貼り付けて実行）。

3. **設定ファイルを作る**
   `lib/config.sample.php` をコピーして `lib/config.php` を作り、手順1の情報を記入します。

   ```php
   'db' => [
       'host'     => 'localhost',      // CoreServerに表示されたホスト名
       'port'     => 3306,
       'name'     => 'xxxx_zonbi',
       'user'     => 'xxxx_zonbi',
       'password' => '********',
   ],
   'base_url' => 'https://example.com/oshi',  // 設置先URL（空欄なら自動判定）
   ```

4. **アップロード**
   FTP（またはファイルマネージャー）で、このフォルダの中身を `public_html/` 以下の好きな場所（例 `public_html/oshi/`）にアップロードします。
   `.htaccess`（ルート・`lib/`・`sql/`）も忘れずにアップロードしてください（隠しファイル扱いのFTPソフトに注意）。

5. **PHPバージョン**
   コントロールパネルのサイト設定で PHP **8.0 以上**（推奨 8.2 以降）を選択します。

6. **SSL（https）を有効化**
   管理用URLにキーが含まれるため、無料SSL（Let's Encrypt）を有効にして https で使ってください。

7. ブラウザで `https://example.com/oshi/` を開き、セッションを作成できれば完了です。

### 動作確認できない場合
- 「lib/config.php がありません」→ 手順3を確認
- 500エラー / DB接続エラー → `config.php` のホスト名・DB名・ユーザー・パスワード、PHPバージョンを確認
- `https://example.com/oshi/lib/config.php` をブラウザで開いて **403 になること** を確認してください（設定が見えないことの確認）

## アップデート時のデータベース更新

すでに `sql/schema.sql` でテーブルを作成済みの場合、新機能のために次のSQLを **1回だけ** phpMyAdmin で実行してください
（DBを選択 →「インポート」でファイルを選ぶ、または「SQL」タブに貼り付けて実行）。既存のデータはそのまま残ります。

| ファイル | 内容 |
|---|---|
| `sql/migrations/001_add_show_all.sql` | 「みんなの依頼を公開」機能の列を追加 |
| `sql/migrations/002_add_event_url.sql` | 「イベントURL」欄の列を追加 |
| `sql/migrations/003_add_google_login.sql` | 代行者のGoogleログイン用のテーブル・列を追加 |
| `sql/migrations/004_add_moderation.sql` | 運営者コンソール・危険ワード検知・通報・登録時の記録 |

新しく設置する場合は `sql/schema.sql` だけでOKです（上記は含まれています）。

## セキュリティについて
- 管理用URLは推測できないランダムなキー（128bit）付き。DBにはハッシュのみ保存しています。**管理用URLは他人に共有しないでください。**
- 依頼者の「自分の依頼」判定は、セッションごとのランダムな編集キー（Cookie）で行います。DBにはハッシュのみ保存。編集キーを含む「あなた専用の編集URL」を知っている人はその依頼を変更できるため、他人に教えないよう案内しています。代行者は管理ページからいつでも全件を編集できます。
- SQLはすべてプリペアドステートメント、出力はエスケープ、フォームはCSRFトークンで保護しています。
- CSVは Excel の数式インジェクション対策済みです。
